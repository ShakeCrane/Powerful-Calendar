# Powerful Calendar — 产品与架构决策基线（G1–G5）

状态：**研究基线 / 已确认产品意图**，不是已经实现的功能清单。
更新时间：2026-10-19。项目的实现代码仍是 Android MVP v0.1；不得把本文件当成已有功能的验收报告。
本文件依据用户连续多轮 Grilling 和最新补充整理；后续若发生冲突，以用户更新的明确决定优先。
重要：此阶段**只写研究文档，不改源代码、不部署、不做迁移操作**。

## 1. 产品定位与唯一数据源

PowerCal 是 Android 原生的一站式个人时间信息中枢，时间轴是主交互界面。
本地 PowerCal 对象库是迁移完成后的**唯一日常权威数据源**：外部日历/闹钟/文件/截图/自然语言等异步导入，通常只迁入一次；外部数据不参与长期实时双向同步。
外部原始数据默认不主动删除，也不声称能控制所有厂商系统闹钟；交接完成后应提示用户检查并手动关闭旧提醒，避免重复响铃。
对外可按事件/类型/账户的派发规则导出到系统日历、ICS 等，但**派发成功不是本地对象提交的前提**，且派发产生的副本不能反向变成主数据源。
导入步骤：发现源能力 → 读入暂存 → 转换 → 校验 → 按源 ID 精确去重/可疑项人工决策 → 本地提交 → 迁移交接提示。推荐导入范围可选择，默认未来数据并允许扩展历史。
所有异步操作必须可观测、可取消、可重试，避免“部分失败却宣告迁移完成”。

## 2. 对象协议与行为分离

- **内部类型继承**：共享 TemporalObject 身份，至少 ActivityEvent（活动）、AlarmEvent（独立闹钟）、TaskEvent（任务）三种子类型；外部采用 Adapter，不把内部类型与 Android/ICS 字段直接绑定。
- 对象类型可变而 objectId 不变（G5-01=A）；类型转换必须保留版本史、校验新字段、撤销不适用行为，不能只改 discriminator。
- 活动可关联独立闹钟；普通提醒是 Trigger。一个 Trigger 可被投影到左侧闹钟区，但不因此生成新的 AlarmEvent（G3-04=A；G4-02=C）。
- 规则和实例分离（G2-05=B、G4-03=A）：保留 RecurrenceRule、Occurrence、Exception；可见范围内动态展开，执行层只安排未来近期所需触发；单次拖动默认修改本次，也可选本次及以后/整个系列（G5-03=A）。
- 时间需保留语义：绝对时刻、具时区的墙上时间、重复规则与显式时区策略；独立闹钟默认当地墙上时间，活动默认创建时指定时区，均允许覆盖（G3-05=B；G4-04=A）。
- 没有可定位时间的 TaskEvent 存在于未安排收件箱，而不伪造时间坐标（G5-02=A）。收件箱 UI 待下一轮讨论。
- 对象优先级与通知/响铃强度独立；对象生命周期、调度生命周期、单次响铃生命周期不得压缩为同一个 status。

## 3. 中央时间轴交互基线

- 屏幕中央固定**竖直时间刻度轴**，上早下晚；左侧 AlarmEvent/可展开的响铃 Trigger，右侧 ActivityEvent 和已获得时间锚点的 TaskEvent。
- 横跨左右的一条美观**水平线**标识当前时刻；它随时间轴位置变化，**不固定为视口中心**。
- 首次进入默认今天、12:00 在可视区正中，普通日期目标完整一天可见。这里是**初始取景**，不是滚动锁；用户可以无限连续上下滑动，经过午夜也不中断（G4-08=A 和用户补充）。
- 正常返回保留视角，显式点击“今日”重置到今天 12:00（G5-05=A）。
- 两指连续缩放，按手指焦点保持对应时间不漂移，动态改变刻度/细节；限制**一个屏幕高度对应 4–48 小时**（G5-06=A）；不允许比例无上限膨胀或缩小。
- 夏令时特殊日真实经过时间要连续（G5-04=A）；23/25 小时的一天与“严格显示 24 小时”的要求冲突时，优先时间坐标正确和 12:00 视觉锚点，特殊日不强求 00:00–24:00 恰好填屏。
- 重叠事件按“开始越早越靠内”从中轴向两侧安排；按稳定的重叠组分轨，已结束的轨道可复用，不能仅因视口微小滚动就突然改变轨道。
- 手机窄屏轨道不足时采用折叠/摘要提示，展开或缩放后显示；真实事件高度与可点击 hit target 可不同，不修改真实时间含义（G3-06=C；G4-09=A）。
- 长按进入拖动预览，按缩放自适应吸附；松手先出现**同一编辑器的紧凑确认模式**，可展开成完整 Popup；未经确认不持久化，必须提供撤销或安全退出（G3-07=A；G4-10=C；G5-07=A；G5-08=A）。
- 时间轴视觉与手势需作为独立 UI 性能/交互课题验证；绘制/布局应基于时间坐标、可视区域和稳定对象身份，不直接对整个超长列表粗暴 scaleY。

## 4. 统一 Popup / AI 草稿

- 所有创建、修改、拖动确认都进入**同一逻辑编辑器**，允许紧凑/完整两种模式；精简字段优先，高级字段按需展开（G2-08=A）。
- AI API 由用户自行配置；接受自然语言、截图、结构化数据，AI 负责对模糊时间做语义推断，输出符合 PowerCal 协议的候选操作；确定性协议校验仍需执行。
- AI 不直接将结果写库。用户确认每个操作，AI 可建议新增/修改/删除，但提交时检查对象版本和差异；要发送既有日程上下文给第三方 API 时按任务最小化选取并事先获得用户授权（G3-09=B；G4-11=A；G5-11=A）。
- AI 识别多个事件时，单个 Popup 内**分页**，左右切换；每成功保存一页，就从待处理队列移除一页；剩余未保存页是可恢复草稿（G3-08=B）。
- 保存页具有独立提交与去重身份，任何崩溃或反复点击都不应产生两条相同事件。
- Popup 的动画、尺寸、左右滑页与收件箱关系尚未定稿，不要提前假设已同意具体交互。

## 5. 执行与可靠性

- 对象数据先可靠写库，随后异步 reconcile 调度；须有可查询的“调度中/成功/失败/权限缺失”状态（G4-05=A）。
- 保存新版本之后，旧版 Android PendingIntent 即使迟到，也必须经 objectId + occurrenceId + triggerId + revision 校验才能产生副作用（G5-09=A）；调度操作幂等、持久化，可重试。
- 必须区分普通提醒（允许显示近似时刻/延迟风险）和必须准时的闹钟；精确权限不足时明确引导授权或外部时钟兜底，**不能静默标记为成功**（G4-06=A）。
- Snooze/跳过一次只影响当前 Occurrence，不修改未来重复系列（G4-07=A）。
- 重启、应用升级、时区改变、权限变化后应 reconcile；对于错过的闹钟允许短暂宽限内补响，超过阈值仅记录错过并提示；具体宽限阈值待定（G5-10=A）。
- Android 具体能力受系统版本、厂商节电政策、精确闹钟权限、通知权限及应用商店政策制约，真机测试前不得承诺所有机型的“100% 按时响”。

## 6. 数据安全和备份

- PowerCal 是唯一数据源，因此**完整原生备份/恢复优先**（G5-12=A），不得以有损 ICS 备份冒充完整恢复。
- ICS/JSON/平台 API 互操作仍保留，但应明确有损字段和不支持的类型；导出前可以提示潜在信息损失。
- 迁移暂存、未保存 AI 草稿和任务收件箱均要有明确的数据保留/删除策略。
- 不应把 API Key 明文写进可导出的事件文件，也不应默认向 AI 提供完整时间轴。
