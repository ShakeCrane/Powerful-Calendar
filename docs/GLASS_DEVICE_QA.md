## 帧时长取证

先在设备设置选定真实 60Hz 或 120Hz，记录实际刷新率；不要只凭厂商标称推断。
在同一 APK 和同一组 100 卡数据下分别取时间轴滚动缩放、卡组快速翻页和键盘编辑三个场景。

```powershell
E:/android-sdk/platform-tools/adb.exe devices -l
E:/android-sdk/platform-tools/adb.exe shell dumpsys gfxinfo dev.powerfulcalendar reset
# 手工执行一个场景约 30 秒后导出；每个场景重置一次。
E:/android-sdk/platform-tools/adb.exe shell dumpsys gfxinfo dev.powerfulcalendar framestats > frames-60hz-timeline.txt
```

建议同时使用 Android Studio System Trace / Perfetto FrameTimeline，区分 UI thread、RenderThread、GPU 与 SQLite 竞争。
记录 P50/P90/P95/P99、最长帧、Janky frames 占比、输入时丢帧、内存与 GC；禁止用单元测试总耗时充当帧时长。
60Hz 单帧预算 16.67ms，120Hz 预算 8.33ms；这些是预算，**本轮没有测出 P95 或卡顿率**。

## 可复现的软件证据

`GlassComposeTest`：API 35、模拟语义/布局/点击/合成手势，部分使用真实 Robolectric SQLite。
`GlassRenderTest`：API 34、Robolectric native graphics + 软件 Canvas，360×800 mdpi 固定样例；输出 `app/build/reports/glass-ui/*.png`。
弹窗图将 Activity 和 Dialog 两个视图绘制到同一软件画布，背景是半透明模拟玻璃，不是设备截图或 GPU 背景模糊。
截图曾帮助发现并修复月历零宽网格与弹窗深色内容色继承问题；没有据此宣称真实触控或动画验收完成。
