# PC-ISSUE-085 — Split a recurring series from a selected occurrence forward

Date: 2026-10-24

Candidate: `REC-P0-079` (reconstructed P0; historical mapping remains `UNMAPPED`)

Status: **CORE TRANSACTION EVIDENCE PASS / REC-P0-079 NOT TESTED / overall freeze HOLD**

## Finding

`CORE_CONTRACT_FREEZE_2026-10-21.md` §7 allows a future-rule edit to truncate the old object and create a new independent event sequence. `PowerStore` had no atomic core operation for editing one original occurrence and the following series. The implementation also needed to preserve the existing identity when the selected occurrence is the first *active* occurrence, including when earlier generated slots have all been excepted.

The regression case selects `2026-10-22T07:30` in a three-slot daily series whose October 20 and 21 slots are exceptions. The selected slot is the first non-skipped occurrence. Under the old `selectedIndex == 0` guard, the operation incorrectly created event sequence 2 instead of applying the edit to sequence 1. A second edge appeared when the form moved the series anchor to October 22: the old total count of three was retained, creating two extra occurrences instead of keeping only the one remaining slot.

## Change

- Added `PowerStore.saveThisAndFutureRecurringEdit(...)`. It validates the editor lease, revision, selected original slot and active range, then atomically truncates the old series and writes the edited future as a new identity.
- Migrates only future exception, override and completion keys that are still generated by the new rule. Both records, commit history entries, draft cleanup and desired schedule intents share one SQLite transaction.
- Added `RecurrenceEngine.hasEarlierActiveOccurrence(...)`. It distinguishes the first generated slot from the first non-excepted slot inside the active date range. If no earlier active occurrence exists, the edit updates the existing sequence as a whole-series change and does not allocate another identity.
- When this first active occurrence becomes the edited anchor and the finite count was left unchanged, the existing identity receives only the remaining count from the selected slot. Earlier skipped keys are excluded from the new projection.
- Added persistence and injected-insert-failure rollback coverage, plus regressions for the first generated slot and for earlier slots all skipped.
- No UI files, database schema, or user data changed. This report signs off the core transaction only; it does not claim a connected editor scope-selection flow or Android device behavior.
